The script serves repository files on localhost, launches headless Chrome using a temporary profile, loads the production detector and OCR worker assets, and writes `pic1.ocr-result.json`. It closes the browser and server; the temporary browser profile remains in the OS temporary directory to avoid Windows file-lock races.

Run `node scripts/run_scanner_ocr_fixture.js --ui --report` for the actual page smoke test. This lets the page load its normal scripts, selects the local screenshot through its file input, waits for automatic detection/OCR/rating, checks all five rows and verifies Stop clears the result permanently. Its report is `pic1.ui-result.json`. CDP records page and attached worker request URLs/methods, and rejects observed external or non-GET requests and JavaScript exceptions. This is observed network evidence for the tested path; browser internals and other untested paths are outside that claim.

The explicitly labelled `forced-first-pass-failure` route deliberately replaces the real worker's first full-panel output with blank text and missing evidence. Five subsequent single-line calls perform actual OCR on the screenshot pixels. The harness requires exactly six worker recognition calls and correct fallback rows/scoring. This verifies fallback execution under an injected failure; it does not reproduce the user's later live capture or establish accuracy for its unknown/clipped labels.

This evidence does not establish 99% recognition accuracy, unsupported-layout rejection, localization support, game value constraints, live-stream reliability, background monitoring, or stable animation/change detection. More independently labelled screenshots and live capture trials are required.
