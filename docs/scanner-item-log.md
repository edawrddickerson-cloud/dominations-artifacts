# Crafting item log

War and Main (Multiplayer) stat observations are stored separately: each label summary has a `hall` and its own values and read counts. Diagnostic deduplication includes hall and item category, so an identical stat read in the other hall is retained. Item entries and diagnostic scans include `hallSource` to distinguish crafting-label detection, original percentage-tier detection, and the selected Hall fallback. The current hall and its source are displayed beside the item category.

Pottery/Jewelry identify Main, Equipment and explicit War Weapon/Armor labels identify War. Original signed 3% tiers identify War, while 11% tiers identify Main. A 6% tier is shared by Main Green and War Blue and cannot distinguish halls. Inferred percentages do not determine hall. A 1% tier or conflicting tier evidence uses the selected Hall; choose Main or War in the header when the image is ambiguous. Retries with differing halls are not combined. Existing label summaries without hall evidence remain unclassified rather than assigning their mixed historical values to either hall.

The crafting scanner logs the best recognised rows for each detected artifact encounter. Save logs in this browser is enabled by default and remembered locally. Reads and accepted corrections save automatically, and reopening the page restores previous sessions. Each page session prefixes item IDs so new encounters cannot overwrite restored items. Manual and automatic OCR retries update the current item rather than adding another. Accepted corrections remain protected from subsequent OCR retries. Partial reads remain marked as needing review, and repeated perk rows are preserved in order.

Item identity follows the scanner's stable image change detection, independently of retry counters and recognition settings. Identical stats do not identify an item: separate encounters can represent separate crafts. A transition must be captured to distinguish two identical crafts. Moving away and returning, reconnecting, or materially changing the crop can create another entry. This is an encounter log rather than a permanent inventory identity system.

Export Item Log and Names downloads JSON version 2 with an `items` array alongside the existing diagnostic `scans` and `labels`. Each item includes its first and latest timestamps, hall, expected row count, ordered stats, validation/correction flags, and available unlocked-star information. Diagnostic scans may include multiple attempts for one item; use `items` for the deduplicated log.

The log contains text only and is limited to 5,000 items and 5,000 diagnostic reads across saved sessions. Stop Scanning retains it. Turning saving off removes the browser's saved copy while retaining the current tab's log; export before refreshing in that mode. Clear Item Log and Names clears both items and diagnostic observations, including their saved copy. Storage failure shows a message recommending export. Saved logs belong to this browser and site origin; they do not sync between devices and clearing browser site data removes them. Use one crafting scanner tab at a time: simultaneous tabs can overwrite the saved snapshot. Nothing is automatically added to the artifact collection or perk settings.

Verification: `node scripts/test_scanner_collection.js` and `node scripts/test_scanner_reading.js` cover retry identity, better-read retention, corrections, separate identical crafts, export isolation, and stale OCR. Mocked image changes do not establish live game transition detection accuracy.
