# Crafting item log

October 29: Full Item Log includes local bounded per-field evidence and grouped unverified `titleCandidates`. Stat Evidence includes `artifactTitleCandidates`. The existing Scanner diagnostics list includes missing and questionable accepted titles; `not-captured` distinguishes older entries without retained title OCR. Stronger reviewed title evidence can update a bound encounter even when its stat retry is worse. Manual titles remain protected; no historical title is changed just because a catalogue candidate exists. See [field evidence](scanner-recognition.md#independent-field-evidence-29-october-2026).

The crafting title is read separately from the category and saved with the logged artifact. Compact entries show that name, the original `firstSeen` timestamp as `yyyy-mm-ddThh:mm:ss` UTC, hall/category, status and Keep. Expand an entry for its stats and optional name correction. Names and timestamps survive retries and reopening. Repeated names within the same profile, hall and category display a shared count; they do not block distinct crafts with the same name. Existing unnamed entries remain unnamed until corrected or read again in their original encounter.

Verification: `node scripts/run_scanner_ocr_fixture.js --crafting-log --summary` reads the title from the real `pic1.png` screenshot through the production pipeline and checks timestamp formatting, compact entries, retry identity, repeated names, corrections and reopening. This fixture does not establish title accuracy for every artifact or layout.

War and Main (Multiplayer) stat observations are stored separately: each label summary has a `hall` and its own values and read counts. Diagnostic deduplication includes hall and item category, so an identical stat read in the other hall is retained. Item entries and diagnostic scans include `hallSource` to distinguish crafting-label detection, original percentage-tier detection, and the selected Hall fallback. The current hall and its source are displayed beside the item category.

Pottery/Jewelry identify Main, Equipment and explicit War Weapon/Armor labels identify War. Original signed 3% tiers identify War, while 11% tiers identify Main. A 6% tier is shared by Main Green and War Blue and cannot distinguish halls. Inferred percentages do not determine hall. A 1% tier or conflicting tier evidence uses the selected Hall; choose Main or War in the header when the image is ambiguous. Retries with differing halls are not combined. Existing label summaries without hall evidence remain unclassified rather than assigning their mixed historical values to either hall.

The crafting scanner logs the best recognised rows for each detected artifact encounter. Save logs in this browser is enabled by default and remembered locally. Reads and accepted corrections save automatically, and reopening the page restores previous sessions. Each page session prefixes item IDs so new encounters cannot overwrite restored items. Manual and automatic OCR retries update the current item rather than adding another. Accepted corrections remain protected from subsequent OCR retries. Partial reads remain marked as needing review, and repeated perk rows are preserved in order.

Item identity follows the scanner's stable image change detection, independently of retry counters and recognition settings. Identical stats do not identify an item: separate encounters can represent separate crafts. A transition must be captured to distinguish two identical crafts. Moving away and returning, reconnecting, or materially changing the crop can create another entry. This is an encounter log rather than a permanent inventory identity system.

The saved crafting log uses JSON version 2 with an `items` array alongside the existing diagnostic `scans` and `labels`. Each item includes its first and latest timestamps, hall, expected row count, ordered stats, validation/correction flags, and available unlocked-star information. Diagnostic scans may include multiple attempts for one item; use `items` for the deduplicated log.

The log contains text only and is limited to 5,000 items and 5,000 diagnostic reads across saved sessions. Stop Scanning retains it. Turning saving off removes the browser's saved copy while retaining the current tab's log; turn saving back on before using the Profiles backup in that mode. Clear Item Log and Names clears both items and diagnostic observations, including their saved copy. Storage failure shows a message recommending export. Saved logs belong to this browser and site origin; they do not sync between devices and clearing browser site data removes them. Use one crafting scanner tab at a time: simultaneous tabs can overwrite the saved snapshot. Nothing is automatically added to the artifact collection or perk settings.

The Profiles section has a **Back up / restore saved data** panel. Export Backup downloads a versioned JSON file containing all planner `dn-` settings (including profiles and crafting logs) and all IndexedDB inventory/Collection records, including artwork and stat metadata. Keep this file separately and export again after changes. Import Backup accepts this full backup format; older item-log/inventory exports remain useful for inspection but cannot be restored through this panel. Restore replaces all saved planner data for this browser/site, after confirmation and a download of the current data as a safety copy. Stop scanning and close other planner tabs first. Invalid files are rejected before writes; storage errors abort the artifact transaction and roll settings back. No data is uploaded. Unsaved current recognition and tab-only diagnostic names are outside the backup.

Verification: `node scripts/test_local_backup.js` covers backup validation, metadata round trips, unrelated storage isolation and rollback. `node scripts/test_scanner_collection.js` and `node scripts/test_scanner_reading.js` cover retry identity, better-read retention, corrections, separate identical crafts, export isolation, and stale OCR. Mocked image changes do not establish live game transition detection accuracy.
